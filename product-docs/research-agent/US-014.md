# US-014: Backlog Integration – Gong (Revenue Intelligence / Calls)

## Metadata
- **Repo**: `Product-OS-Research-Agent`
- **ID**: US-014
- **Status**: `create`
- **Branch**: (not yet created)
- **Dependencies**: US-003 (integration service), US-007 (mapping pattern). Gong provides call/meeting data and transcripts; maps to “meeting_note” or “customer_call” style entities.

## Target Users
- **Primary**: Admins configuring Gong as a data source for Product OS.
- **Secondary**: PMs using call transcripts and deal/customer context as evidence in Research Agent (e.g. “what did customers say about pricing?”, “calls mentioning feature X”).

## Goal

Deliver a **dedicated Gong integration** so Product OS can connect to Gong, configure which calls/workspaces to sync, and ingest call metadata and transcripts into the Research Agent as searchable entities with citations, enabling voice-of-customer and revenue context in product research.

## Problem Statement

Gong holds sales and customer call recordings, transcripts, and CRM-linked context. PMs need this signal alongside backlog and support data. Without an integration, Gong content is siloed. This integration must support API auth, call listing and transcript retrieval, and mapping of calls/transcripts to Product OS entity types (e.g. meeting_note or dedicated customer_call) so the Research Agent can answer questions with evidence from calls.

## Technical Context (Research Summary)

- **Auth**: API key (access key + secret). Obtained by Gong admin from Admin center → Settings → Ecosystem → API. Basic auth with BASE64(access_key:secret) in Authorization header. OAuth available for Gong Collective apps; for direct integration, key-based auth is standard.
- **Endpoints** (v2, `https://api.gong.io` or region-specific):
  - **Calls**: `POST /v2/calls/extensive` — list/filter calls (date range, content selectors). `POST /v2/calls/transcript` — get transcript by call IDs (payload: `{"filter": {"callIds": [...]}}`). Transcript returns sentences with start/end times and text.
  - **Users**: `GET /v2/users` — list users (paginated, default 100).
  - **Meetings**: `GET /v2/meetings` — scheduled meetings.
  - **Stats**: `POST /v2/stats/activity/aggregate` — activity/performance.
- **Limitation**: No native transcript search API; integration must index transcript text locally (e.g. chunk and embed in Product OS) for search.
- **Entity mapping**: Calls → Product OS “meeting_note” or “customer_call” with fields: title (e.g. call subject), transcript/summary, participants, date, deal/account if available. Optional: link to Gong call URL for citation.

## Non-Goals

- Gong Data Cloud / Snowflake path (API-only for this story).
- Pushing data back to Gong.
- Real-time transcript streaming; batch sync of completed calls only.

## Acceptance Criteria

*(To be refined in Phase 2.)*

- **AC1 – Connect**  
  Admin can connect Gong in Product OS (API access key + secret). Credentials stored securely; connection status visible in UI.

- **AC2 – Configure sync scope**  
  Admin can set date range and optionally filter by workspace, call type, or other Gong filters. Selection persisted and used by sync.

- **AC3 – Entity and field mapping**  
  Admin can map Gong calls (and transcript content) to Product OS entity type(s): e.g. meeting_note or customer_call, with canonical-like fields (title, transcript/summary, attendees, date, source_system=gong). Follows US-007 mapping pattern where applicable.

- **AC4 – Sync and ingestion**  
  Sync job lists calls in scope, fetches transcripts via `/v2/calls/transcript`, normalizes to entities + chunks (transcript text chunked for search), and ingests into Research Agent store and vector index.

- **AC5 – Search and citations**  
  Ingested Gong calls/transcripts appear in `list_sources` and `search_memories`; PMs can ask questions about what was said in calls and get answers with citations to Gong (call URL or call ID).

- **AC6 – NFRs**  
  API credentials stored server-side only; no secrets in frontend or logs. Pagination and rate limits respected; clear errors for invalid/expired credentials.
