# US-015: Backlog Integration – SharePoint (Microsoft 365)

## Metadata
- **Repo**: `Product-OS-Research-Agent`
- **ID**: US-015
- **Status**: `create`
- **Branch**: (not yet created)
- **Dependencies**: US-003 (integration service), US-007 (mapping pattern). SharePoint provides sites, lists, and files; maps to Product OS documents, optional task/list entities.

## Target Users
- **Primary**: Admins configuring SharePoint / Microsoft 365 as a data source for Product OS.
- **Secondary**: PMs searching SharePoint documents and list data (e.g. specs, wikis, task lists) via Research Agent with citations.

## Goal

Deliver a **dedicated SharePoint integration** so Product OS can connect to Microsoft 365 (via Microsoft Graph), select sites and optionally lists/libraries, map content to Product OS entity types (e.g. document, PRD, or list items to task/roadmap_item), and sync content into the Research Agent for search and evidence in chat.

## Problem Statement

Many organizations store PRDs, specs, and team wikis in SharePoint. Without an integration, this content is invisible to the Research Agent. The integration must support Azure AD / Microsoft Graph auth, site and drive/list selection, and mapping of documents and list items to canonical Product OS entities so PMs can search and cite SharePoint content.

## Technical Context (Research Summary)

- **Auth**: Microsoft Graph (Azure AD). Delegated (user) or app-only. For app-only: client credentials; may require tenant settings (e.g. `Set-SPOTenant -DisableCustomAppAuthentication $false` for custom app-only if using legacy REST). Recommended: Graph with Sites.Read.All or Files.Read.All (and Sites.Selected for least privilege where possible).
- **API**: Microsoft Graph `https://graph.microsoft.com/v1.0`.
  - **Sites**: `/sites/root`, `/sites/{site-id}`, `/sites/{site-id}/drive` (default doc library), `/sites/{site-id}/lists`, `/sites/{site-id}/lists/{list-id}/items`.
  - **Drive items**: Files and folders under a site’s drive. Use `select` and `expand` to limit payload.
- **Content**: Documents (e.g. .docx, .pdf) and list items (task lists, custom lists). Documents can be read (content) via Graph; list items have fields. Mapping: document library → document/PRD-like entities; task list → task or roadmap_item if applicable.
- **Entity mapping**: SharePoint site/drive → “document” or “prd”; list → task, roadmap_item, or generic “list_item” with configurable field mapping to canonical fields.

## Non-Goals

- SharePoint on-premises / legacy REST-only (Graph-first; classic REST only if Graph is insufficient and documented).
- Full Graph Teams/OneDrive scope; focus on SharePoint sites and their drives/lists.
- Real-time subscription/webhooks in MVP; batch/scheduled sync first.

## Acceptance Criteria

*(To be refined in Phase 2.)*

- **AC1 – Connect**  
  Admin can connect Microsoft 365 / SharePoint via Azure AD (OAuth or app registration) in Product OS. Credentials and tenant/site context stored securely; connection status visible in UI.

- **AC2 – Select scope**  
  Admin can choose which SharePoint sites (and within them, which document libraries or lists) to sync. At least one site and one library or list selectable; selection persisted for sync.

- **AC3 – Entity and field mapping**  
  Admin can map document libraries to Product OS entity type(s) (e.g. document, prd) and list types to entity types (e.g. task, roadmap_item). Mapping follows US-007 pattern (entity type → source container, then field mapping).

- **AC4 – Field mapping**  
  For lists: map list columns to canonical Product OS fields. For documents: title, summary/body (extract text where possible), last modified, author. Required canonical fields for chosen entity types must be mappable.

- **AC5 – Sync and ingestion**  
  Sync job fetches selected sites/lists and document metadata (and content where supported by Graph), normalizes to entities + entity_fields + chunks, and ingests into Research Agent store and vector index. Incremental sync by last modified when supported.

- **AC6 – Search and citations**  
  Ingested SharePoint content appears in `list_sources` and `search_memories` with correct entity_type and citations to SharePoint URLs (e.g. item view or document link).

- **AC7 – NFRs**  
  Credentials stored server-side only; minimal Graph scopes; no secrets in frontend or logs. Clear errors for consent or permission failures.

## NFRs / Constraints

- Large libraries: pagination and optional date/last-modified filters to limit sync volume. Document content extraction may require format support (e.g. Office Open XML, PDF) and size limits.
